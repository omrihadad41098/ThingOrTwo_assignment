Thing or Two - implementation spec - 20 November 2026

SeatRush

A ticket drop where a seat is sold at most once, a hold is all or nothing, and an expired hold cannot be bought even if no cleanup job has run. Build this. Do not reopen a decision unless a test proves it wrong.

Stack: NestJS, PostgreSQL 16, pg (raw SQL), Zod, React 18, TypeScript, Vite, Docker Compose. Code is split into backend/ and frontend/. No Redis, no in-process mutex, no TypeORM schema sync, no floating-point money. API on port 3000, web on 5173. Fans are the header X-Fan-Username. The active name is in sessionStorage so two windows are two fans. Build the required product before the extra credit at the end.

1. System

An admin creates an event: grid, price zones in agorot, show time, drop time. Anyone can look. At the drop, a fan holds 1 to 4 seats for HOLD_TTL_SECONDS (default 300) and checks out. Checkout is the purchase. There is no payment and no password.

API processes are stateless. PostgreSQL decides. A hold is a row with expires_at. The row lock lasts for the transaction, milliseconds, never for the five minutes. The winner is the first commit. Other transactions re-read the locked row and roll back, so losers leave no hold row. Map reads take no locks. They compute status from the seat plus the hold clock, using now() inside the database. A dead sweeper changes nothing about correctness.

2. Requirements

FR-11Best available holds N side-by-side seats in one row, in one transaction. Optional max price and zone. Order: nearest row, then block whose middle is closest to the row middle, then lower start. Nothing fits: reject, hold nothing.

FR-14Owner can release a live hold. Seats return and leave the cap. Another fan gets 403.
FR-15Screens: name gate, event list with countdown, map by zone, selection or best available, hold countdown, checkout, my tickets. Poll the map. A double click sends one hold. Show the server's message.

Also required, not product rules. docker compose up --build migrates and seeds Demo Night already on sale. OpenAPI at /docs and /docs-json. TTL and cap come from the environment and a bad value refuses to boot. One test command. A real-PostgreSQL test where many holds hit one seat and exactly one wins. Human error sentences. 3. Decisions

A hold is live only when status = 'active' and expires_at > now(). There is no expired status. Use that one predicate for the map, the cap, and checkout.

ChoiceWhy this, and what was set aside
Seat row is the mutex, via SELECT FOR UPDATE. Cap mutex is user_event_locks.An in-process lock dies at the second API. Redis is a second source of truth. Serializable isolation also aborts innocent best-available scans. Read committed plus these locks is the protocol.
Lock only for the transaction.A lock held for the TTL would freeze the drop. The five minutes are expires_at.
Lock seats one at a time, in (row_index, seat_number) order. Lock order is user row, then hold row if it exists, then seats.One unordered SELECT FOR UPDATE can deadlock overlapping requests. An event-wide lock makes the drop single-threaded. Creating a hold does not update the old hold row: that deadlocks with checkout, which locks the hold first.
Cap is a count under the user lock, not a counter column.A stored counter drifts when a hold expires with no update. The count query uses expires_at. It counts seats, not holds. Two fans do not queue on each other.
Reads: own pool, default_transaction_read_only, no cache, no replica.A shared pool lets buyers starve the map. A replica can show a sold seat as free. Staleness is only uncommitted work, which is the safe direction: a fan may click a seat that was just taken and will be told.
Explicit holds wait up to 2s. Best available uses NOWAIT inside a savepoint, at most 8 probes, one outer transaction.The fan asked for those exact seats, so a short wait is fair. Best available must not sit behind a seat it will not get. SKIP LOCKED treats "locked" as "gone".
Unique orders.hold_id. If an order exists, return it before checking expiry.The brief wants the same order back. A fan who bought and retries after five minutes still gets the tickets. A fan who never bought is refused.
First commit wins. No waiting room in this build.The brief requires one winner, not a moral ordering of packets.
Raw SQL, not an ORM, for writes. React with no Redux and no component kit.The graded part is the transaction. Four screens do not need a store. Seat buttons should be plain.

Assumptions, where the brief was silent. Usernames match ^[a-z0-9][a-z0-9_-]{0,31}$ after trim and lower. Events are immutable. No aisles: "together" means consecutive numbers in one row. A request is at most 4 seats even if the cap is higher; the cap still applies across holds. Manual selection need not be contiguous. Several live holds are allowed. drop_at is strictly before starts_at. Prices are integers >= 0. Caps: 1-60 rows, 1-100 seats per row. Row labels are spreadsheet-style (0 is A, 25 is Z, 26 is AA). Released and expired holds do not count. Releasing an already released hold is 200. Checkout of an expired hold with no order is 409. Polling every 2 seconds is the live map. Language is English. Display money as ILS 349.35 from integer agorot, not from a float.

Leave these out. No Redis. No lock held for the TTL. No float money. No synchronize: true. No trust of seats.state without the live-hold predicate. No availability check that commits before the insert. No "this seat is yours" before HTTP 201. No active fan in localStorage. No second function that inserts holds.

4. Schema

One file, backend/src/db/sql/001_init.sql. The runner creates schema_migrations, takes session advisory lock 814200 on a dedicated connection, applies the file, seeds, unlocks, then releases the connection. A pooled connection that returns to the pool while locked keeps the lock. gen_random_uuid() is built into PostgreSQL 16.

CREATE TABLE users (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  username text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE events (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL, venue text NOT NULL,
  starts_at timestamptz NOT NULL, drop_at timestamptz NOT NULL,
  row_count integer NOT NULL, seats_per_row integer NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CHECK (drop_at < starts_at),
  CHECK (row_count BETWEEN 1 AND 60 AND seats_per_row BETWEEN 1 AND 100)
);
CREATE TABLE zones (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id uuid NOT NULL REFERENCES events (id),
  name text NOT NULL, from_row integer NOT NULL, to_row integer NOT NULL,
  price_agorot integer NOT NULL CHECK (price_agorot >= 0),
  CHECK (from_row >= 0 AND to_row >= from_row),
  UNIQUE (event_id, name)
);
CREATE TABLE holds (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id uuid NOT NULL REFERENCES events (id),
  user_id uuid NOT NULL REFERENCES users (id),
  status text NOT NULL CHECK (status IN ('active','released','converted')),
  created_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  CHECK (expires_at > created_at)
);
CREATE TABLE seats (
  event_id uuid NOT NULL REFERENCES events (id),
  row_index integer NOT NULL, seat_number integer NOT NULL,
  zone_id uuid NOT NULL REFERENCES zones (id),
  state text NOT NULL CHECK (state IN ('available','held','sold')),
  current_hold_id uuid REFERENCES holds (id),
  PRIMARY KEY (event_id, row_index, seat_number)
);
CREATE TABLE hold_seats (
  hold_id uuid NOT NULL REFERENCES holds (id),
  event_id uuid NOT NULL, row_index integer NOT NULL, seat_number integer NOT NULL,
  PRIMARY KEY (hold_id, event_id, row_index, seat_number),
  FOREIGN KEY (event_id, row_index, seat_number)
    REFERENCES seats (event_id, row_index, seat_number)
);
CREATE TABLE user_event_locks (
  user_id uuid NOT NULL REFERENCES users (id),
  event_id uuid NOT NULL REFERENCES events (id),
  PRIMARY KEY (user_id, event_id)
);
CREATE TABLE orders (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  hold_id uuid NOT NULL REFERENCES holds (id),
  event_id uuid NOT NULL REFERENCES events (id),
  user_id uuid NOT NULL REFERENCES users (id),
  subtotal_agorot integer NOT NULL, discount_agorot integer NOT NULL,
  total_agorot integer NOT NULL, promo_code text,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT orders_hold_id_key UNIQUE (hold_id),
  CHECK (subtotal_agorot >= 0 AND discount_agorot >= 0 AND total_agorot >= 0
     AND total_agorot = subtotal_agorot - discount_agorot)
);
CREATE TABLE order_seats (
  order_id uuid NOT NULL REFERENCES orders (id),
  event_id uuid NOT NULL, row_index integer NOT NULL, seat_number integer NOT NULL,
  price_agorot integer NOT NULL CHECK (price_agorot >= 0),
  PRIMARY KEY (order_id, event_id, row_index, seat_number),
  FOREIGN KEY (event_id, row_index, seat_number)
    REFERENCES seats (event_id, row_index, seat_number)
);
CREATE TABLE promo_redemptions (
  code text NOT NULL, user_id uuid NOT NULL REFERENCES users (id),
  order_id uuid NOT NULL REFERENCES orders (id),
  PRIMARY KEY (code, user_id)
);
CREATE INDEX holds_live_idx ON holds (user_id, event_id, expires_at) WHERE status = 'active';
CREATE INDEX seats_current_hold_idx ON seats (current_hold_id) WHERE current_hold_id IS NOT NULL;

seats is the mutex and the map. current_hold_id can point at one hold. hold_seats is history and is not a uniqueness constraint. orders.hold_id is one purchase per hold. Price of an unsold seat lives only on the zone; order_seats.price_agorot freezes it at sale. user_event_locks has no counter. Do not add a seat_claims table: a primary key per seat blocks expired seats until something deletes the claim.

Generate seats in the create-event transaction. Inserted count must equal row_count * seats_per_row, or roll back.

INSERT INTO seats (event_id, row_index, seat_number, zone_id, state)
SELECT $event, r.idx, s.n, z.id, 'available'
FROM generate_series(0, $rowCount - 1) AS r(idx)
JOIN zones z ON z.event_id = $event AND r.idx BETWEEN z.from_row AND z.to_row
CROSS JOIN generate_series(1, $seatsPerRow) AS s(n);

Demo seed, only when events is empty, inside the same advisory lock: Demo Night at The Rialto, 8 rows, 12 seats, Stalls A-C at 15000, Circle D-F at 10000, Balcony G-H at 6000, drop one hour ago, show in 30 days. A second boot sees the row and inserts nothing.

Map status, every read, no other version of this:

CASE
  WHEN s.state = 'sold' THEN 'sold'
  WHEN s.state = 'held' AND h.status = 'active' AND h.expires_at > now() THEN 'held'
  ELSE 'available'
END

Labels. Index 0 is A, 25 is Z, 26 is AA. Parse seat ids case-insensitively. Respond with the canonical form.

function indexToLabel(index: number): string {
  let n = index + 1, s = "";
  while (n > 0) {
    s = String.fromCharCode(65 + ((n - 1) % 26)) + s;
    n = Math.floor((n - 1) / 26);
  }
  return s;
}

5. Transactions

The bug to prevent is a check outside the lock. The only availability fact that may guide a write is the row from SELECT ... FOR UPDATE in the same transaction as the insert. An earlier select is a hint. withWriteTransaction is the only way to mutate: BEGIN, SET LOCAL lock_timeout = '2s', SET LOCAL statement_timeout = '5s', callback, commit or roll back, always release the client. SQLSTATE 55P03 and 40P01 become 503 after rollback. Deadlock retries the whole transaction once. "Seat taken" is not retried. Write pool max 10, read pool max 10, connection timeout 2s. Tests set the write pool to at least 50. A failed pool checkout is 503, message Too many people are trying for these seats. Please try again.

User and cap lock, both steps, because ON CONFLICT DO NOTHING does not lock the existing row:

INSERT INTO users (username) VALUES ($1) ON CONFLICT DO NOTHING;
SELECT id FROM users WHERE username = $1;
INSERT INTO user_event_locks (user_id, event_id) VALUES ($id, $event) ON CONFLICT DO NOTHING;
SELECT 1 FROM user_event_locks WHERE user_id = $id AND event_id = $event FOR UPDATE;

Create hold. Explicit selection and best available share this writer. Caller already holds the user-event lock.

  1. Missing event is 404. drop_at > now() is 409 NOT_ON_SALE.
  2. Count used seats. If used + requested > cap, fail before locking seats. Message: You can only hold 4 seats for this show, and you already have 4. Use the real numbers.
  3. Lock each requested seat in order. Explicit holds wait. Best-available probes use NOWAIT.
  4. Classify from that locked row only. Anything not free throws SEAT_UNAVAILABLE and inserts nothing.
  5. Insert the hold with expires_at = now() + make_interval(secs => $ttl). Insert hold_seats. Update each seat to held and the new pointer, AND state <> 'sold'. Each update must change one row.
SELECT s.state, s.current_hold_id, h.status AS hold_status, h.expires_at, h.user_id AS holder_id
FROM seats s LEFT JOIN holds h ON h.id = s.current_hold_id
WHERE s.event_id = $1 AND s.row_index = $2 AND s.seat_number = $3
FOR UPDATE OF s;

No row: 400, B99 isn't a seat in this event. Sold: B3 is already sold. Live and yours: You already hold B3. Live and someone else: Someone just took B3. Several seats get Nothing was held. in front, and a mixed case names both reasons. seatIds lists every blocker. Anything else is free, including a held seat whose clock has passed. Take it by overwriting the pointer. Leave the old hold active; expires_at drops it from the cap. Do not lock its sibling seats in this transaction.

SELECT
  (SELECT count(*) FROM hold_seats hs JOIN holds h ON h.id = hs.hold_id
    WHERE h.user_id = $user AND h.event_id = $event
      AND h.status = 'active' AND h.expires_at > now())
+ (SELECT count(*) FROM order_seats os JOIN orders o ON o.id = os.order_id
    WHERE o.user_id = $user AND o.event_id = $event) AS used;

Release. Lock user, hold, then its seats. Wrong fan: 403 This hold belongs to another fan. Already converted: 409 These seats are already bought. Already released: 200. Live but expired: 409 Your hold has expired. These seats are back on sale. Otherwise set released and free seats whose pointer is still this hold. Update count must equal the hold size.

Checkout. Lock user, then the hold. If an order exists, return it with alreadyExisted: true and do not look at expiry or at a new promo. Wrong fan: 403. Released: 409 This hold was released. Expired and no order: 409 and roll back. Then lock the seats, confirm each is held by this hold, sum zone prices, insert order and lines, set seats sold with a null pointer, set the hold converted. Unique violation orders_hold_id_key (23505) aborts the loser: read the winner's order on a new connection and return 200. Do not treat every 23505 that way. A promo-key violation is 409 PROMO_USED and the hold stays live.

After the single-seat stampede, holds has one row and hold_seats has one row. This query and sold seats with a non-null pointer are both empty:

SELECT event_id, row_index, seat_number, count(*)
FROM hold_seats hs JOIN holds h ON h.id = hs.hold_id
WHERE h.status = 'active' AND h.expires_at > now()
GROUP BY 1, 2, 3 HAVING count(*) > 1;

6. Expiry and best available

At expires_at, checkout fails and the map shows available. The brief allows 5 seconds for a sweeper; this design is correct at the instant, which is inside that bound. Tests move expires_at to now() - interval '1 second' and to 6 seconds ago. Do not sleep. The grader's own run will set a short TTL and sleep; the predicate passes that too.

Sweeper every 10 seconds, SWEEPER_ENABLED default true, tests set false. pg_try_advisory_xact_lock(814201) so three copies do not fight. It only clears a held seat whose hold is not live. It must not run on the checkout path.

UPDATE seats s SET state = 'available', current_hold_id = NULL
FROM holds h
WHERE s.current_hold_id = h.id AND s.state = 'held'
  AND NOT (h.status = 'active' AND h.expires_at > now());

Best available is a pure function plus the shared writer. cells[0] is seat 1. Skip a row on zone or price. A start s is a candidate when s through s+count-1 are free. Rank by row index, then distance, then start.

rowCenter = (1 + seatsPerRow) / 2
blockCenter = (start + end) / 2
distance = Math.abs(blockCenter - rowCenter)

Eight seats, taken {4, 5}, N = 2, row center 4.5. Blocks 2-3 and 6-7 are both distance 2. Lower start wins: 2-3. That geometric pick is B2-B3. The live hold always applies the lone-seat rule, so this room is held as C4-C5.

Inside one transaction: lock the user, check the drop and the cap (a cap failure is LIMIT_EXCEEDED, not "no block"), then up to 8 times load the grid with no locks, call chooseBlock, SAVEPOINT probe, try the writer with NOWAIT. Success releases the savepoint and commits. Seat taken or 55P03: ROLLBACK TO SAVEPOINT and try again. After an error, PostgreSQL accepts nothing except that rollback. Eight lock-only misses: 503. No candidate: 409 No 2 seats together are free in that price range.

Jest and Supertest against the real Nest app and seatrush_test. Each test truncates order_seats, orders, promo_redemptions, hold_seats, holds, user_event_locks, seats, zones, events, users with RESTART IDENTITY CASCADE, then arranges through HTTP. 10. Scale, launch, extra credit

100,000 fans in the first minute. The map read breaks first: that many browsers polling the whole room is on the order of 50,000 queries a second. Writes fail second, and they fail closed. Best available all locks row A first, requests hit the 2 second lock timeout or the write pool, and the fan is told to retry. Commits still take the seat lock, so nobody is double-booked. The launch change is a waiting room and a push of seat deltas. Not this build.

Three API copies. The protection holds. The seat mutex, the cap mutex, the unique order, and the clock are all in PostgreSQL. No sticky sessions. Three sweepers skip via the advisory lock. Three boots share the migration lock, so the demo event is inserted once. Three copies do not fix the poll storm.

Before a real launch, do not build now. Real sessions and an authenticated admin. A payment that sells the seat only when payment commits under the same lock. A waiting room. Push instead of polling. Managed Postgres and backups. An audit log. Rate limits shared across copies. The username header is an impersonation path; the README says so.

11. Cancel, coupons, lone seats, delete fan

These behaviors are part of the running app. Best available on the brief's room returns C4-C5, because the lone-seat rule is always on.

Cancel. After Hold these seats, each live hold card shows Checkout and, beside it, Cancel. Cancel is POST /holds/:id/release with the fan header. 200 frees every seat whose pointer is still this hold and sets the hold released. The page reloads the map so those seats are available and the card is gone. A second cancel by the owner is 200 and does not move seats again. Another fan gets 403 This hold belongs to another fan. An expired hold is 409 and the rows stay as they are. The confirm step does not hide Cancel.

Coupons. The hold card has one text field, Coupon code. The page previews with the same integer math the server uses. Empty or whitespace means no discount. SAVE10 (any case) discount is Math.floor((subtotal * 10 + 50) / 100), then subtract, and the total is never below 0. WELCOME20 discount is min(2000, subtotal), which is 20 shekels. 34935 with SAVE10 is discount 3494, total 31441. Any other non-empty code is unknown.

Checkout reads an existing order first and returns it with alreadyExisted: true and the original totals. A new promo on a replay is ignored. Only when there is no order does it price the code. Unknown is 409 PROMO_INVALID with That coupon code isn't valid. and the transaction rolls back, so the hold stays live. WELCOME20 is inserted into promo_redemptions (code, user_id, order_id) after the order row exists, inside the same transaction. The primary key is the once-per-fan guard across events, because the user lock is per event. A second WELCOME20 is 409 PROMO_USED with WELCOME20 can only be used once. A unique violation on promo_redemptions_pkey is that same 409, not the order-replay path. Only orders_hold_id_key maps to a replay. SAVE10 is not stored in promo_redemptions and may be used on later orders. The client shows the server message and leaves the hold card up.

Lone seats. The rule is always on. The event page has no switch. The seat page refuses a click whose selection would leave a new lone seat. The hold transaction refuses the same choice. oneSeatMode in a hold body is ignored, and there is no environment flag that turns the rule off, so a direct API call cannot skip it.

A seat is lone when it is free and both neighbors are taken, or one neighbor is taken and the other side is the end of the row. Judge the row after the requested seats are treated as taken. Reject only a lone seat that was not already lone before this hold. Seats that were already lone do not reject an unrelated hold. On the worked row (8 seats, A full, B4 and B5 sold, N = 2) every pair in B creates a new lone seat, so best available returns C4-C5. The hold locks every seat in each touched row, in (row_index, seat_number) order, before judging, so the picture cannot change under the check. Sentence, with no extra prefix: That choice would leave a single empty seat stuck on its own. Pick different seats. Code LONE_SEAT, status 409, and no hold row. Best available skips those blocks inside chooseBlock. If the locked picture disagrees, that probe rolls back to its savepoint and tries again, the same way a taken seat does.

Create show. Build this. /admin opens with a form, then the fan list. No login. Create show calls POST /events. Fields are name, tickets go on sale, show starts, rows, seats per row, and zones. The page sends the show name as venue, because that column is still required. A zone has a name, from row, to row, and a price typed in shekels with at most two decimal places, such as 150.00. The page converts that text to integer agorot (150.00 is 15000) and sends priceAgorot. It does not multiply a float. Add zone appends a blank row. Remove is hidden when only one zone remains. Rows are a rectangle: every row has seatsPerRow seats, row A is nearest the stage, and the zones must cover A through the last row exactly once. The drop must be before the show. The API's 400 sentence is shown as written. 201 shows the name, seat count, each zone with its rows and ILS price, and a link to /events/:id. The new show is then on GET /events.

Remove show. Each row on the admin show list has Remove show. That arms Confirm remove and Keep. Confirm remove calls DELETE /admin/events/:id. In one write transaction: lock the event, clear seat hold pointers, then delete promo_redemptions for its orders, order_seats, orders, hold_seats, holds, seats, user_event_locks, zones, and the event. Fans stay. Other shows stay. A missing id is 404 We couldn't find that event.

Delete fan. /admin lists fans from GET /admin/users, newest created_at first. There is no password, matching event creation. A fan row exists only after a hold. Delete User arms a confirm step; Confirm delete calls DELETE /admin/users/:username. Keep aborts. In one write transaction: lock the user, set seats whose current_hold_id is one of that fan's holds back to available with a null pointer, set seats sold on that fan's orders back to available, then delete promo_redemptions, order_seats, orders, hold_seats, holds, user_event_locks, and the user. Events and other fans stay. A missing username is 404 We couldn't find that fan. and deletes nothing. On 200, before the next paint of the name gate: remove that username from localStorage key seatrush.recent, and if sessionStorage key fan is that username, delete the key so the header no longer shows it. The next open of / fetches GET /admin/users again. The deleted name is absent from the chips, the name field, and the header, including after a refresh and after the browser or the containers restart. Do not keep a client list of names that can outlive the users table.
